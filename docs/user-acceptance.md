# 0.3.1 用户视角验收

2026-10-29。先从公开 GitHub 仓库全新克隆，再按 README 安装和启动；随后新建独立项目安装打包制品，验证 npm 命令、类型和实际 SDK 通信。初始公开版本 0.3.0 的常规流程可用；本次扩展失败路径时发现并修复了下列问题。

## 发现并修复

| 触发条件 | 原行为 | 修复后的行为 |
|---|---|---|
| 网关返回 HTML 502 或非对象 JSON | JSON 解析异常，丢失状态和请求编号 | 抛出 `opcpayError/INVALID_RESPONSE`，保留 HTTP 状态、请求编号及重试标记，不暴露网关正文 |
| 修改 `.env` 从 mock 切至 live，仍使用原数据库 | 模拟记录与真实模式混用 | 数据库绑定模式；拒绝跨模式或不明确的旧数据，要求选择新路径，保留原文件 |
| 旧的余额刷新请求晚于扣次请求返回 | 页面显示回扣次前余额 | 仅最新刷新响应可更新页面 |
| 中文密码的 UTF-8 字节跨 HTTP 分片 | 正确密码可能被误判 | 收齐受限长度的 Buffer 后统一解码 |

另补充 SDK/技能 CLI 的符号链接、stdin 导入兼容性；页面收到 HTML 网关错误时提供可恢复的提示。

## 覆盖的操作与失败路径

- 所有 19 个 SDK 方法通过实际本地 TLS 连接验证 HTTP 方法、路径、鉴权和参数；5 个预留财务方法由模拟服务按协议返回 501。
- 401、429、HTML 502、畸形 JSON、null、连接断开、超时和重定向；不自动重试，不将凭证跟随重定向发送。
- 登录、错误密码、会话过期、退出、CSRF、Origin/Host、输入类型/长度、限流、伪造用户/价格/扣减量。
- 实际档位展示、购买请求丢失、同号恢复、未知购买阻止换号、原参数冻结、终态重放、失效二维码、无效购买 URL。
- 无额度、次数/积分扣减、买断/时长访问决策；未确认、处理中、错误请求号/数量/单位均不交付。
- 同号并发不重复扣减，不同操作并发不超扣；额度耗尽后不交付；重复模拟付款不重复增加额度。
- 服务端已扣减但浏览器响应丢失、刷新恢复、交付失败；UNKNOWN/CONFIRMED 状态重启后恢复原操作。
- 支付回跳和伪造 PAID 参数不能授予权益；真实模式不展示模拟付款按钮，模拟付款 API 不存在；HTTPS 会话 Cookie 的 Secure/HttpOnly/SameSite 校验。
- 通知验签的篡改、密钥、时间窗口、事件身份和原文要求；不把验签当作应用级事件去重。
- 两种技能安装、拒绝默认覆盖、更新备份、符号链接保护、命令入口，以及 npm 包不包含环境文件或数据库。

## 复现命令

```bash
npm ci
npm ci --prefix examples/node
npm run test:all
python3 test/browser_example.py
python3 test/browser_failures.py
python3 test/browser_modes.py
```

浏览器测试需要 Python Playwright、Chromium 和 WebKit；TLS 测试需要 OpenSSL。`browser_modes.py` 使用临时自签证书及本地模拟提供方，链路为浏览器 → 示例服务端 → 实际 SDK → 本地 HTTPS 服务，不访问支付宝。只对测试子进程添加 CA，不关闭系统 TLS 校验，不更改系统证书。

## 未覆盖及边界

本机没有配置有效项目 API Key。真实主站仅验证了无效凭证被拒绝（401），没有成功调用真实项目权益、没有真实付款或核销，也没有修改通知配置。不能把本次结果称为支付宝全模式生产验收。真实通知投递、支付宝审核/限额/手机唤起、退款/账单以及微信和其他支付平台都不在已验证范围。

技能验证包含安装、文件与规则检查，没有宣称另一个编程 Agent 已独立完成第三方项目的自动改造。示例为单实例教学用途，没有做多实例数据库竞争、长期压测或全部操作系统验证。

旧示例数据库会保留。升级后如提示模式不明确，请使用新的 `DATABASE_PATH`，不要删除旧文件或把模拟数据迁入真实模式。
