# 接入 opcpay

先确认用户是否已在[一人付官网](https://ai6666.com/opcpay/)创建自己的项目、按项目指引扫码完成支付宝收费配置，并在项目控制台申请 API Key。已有项目和 Key 时直接复用。尚未开通时，先给出官网入口及“创建项目 → 扫码配置 → 申请 API Key”三步指引，并说明官网第 2 步通过扫码或打开支付宝进入支付宝商品页面，页面“授权信息”显示“授权平台：碳基圈”；可以继续编写代码和模拟验证，但不能把安装 SDK 视为完成真实收款接入。

先检查项目的框架、服务端入口、登录身份、数据库和任务交付方式。复用现有结构与页面风格，不以示例登录替换真实账号体系。没有服务端时先增加受保护的服务端路由，不能把 Key 放进浏览器。

用项目服务端环境变量 `opcpay_api_key` 配置 API Key；缺少时保留配置占位并说明位置，勿索取或打印密钥。Node 项目安装 `opcpay`，导入 `opcpay`；其他语言按相同 API 契约集成，不强行迁移框架。

先只读查询 `/capabilities` 和 `/product`，读取商户已配置的收费模式、SKU、实际价格和数量。不重新替用户选择收费方式，不把演示 SKU/价格写进真实项目。接口基址为 `https://ai6666.com/opcpay/api/pay/v1`。

按实际收费模式完成这条业务路径：

- 套餐来自 `/product`；由服务端登录身份确定稳定的 `user_id`，不接受客户端指定用户、价格或扣减量。
- 购买前持久化业务编号、SKU、用户与回跳 URL；`purchase` 的重复请求使用全部相同参数。购买链接是入口，`READY`、回跳和扫码均不能标记某一笔已付款。
- 返回后查询 `access`。买断/时长包只在 `decision=ALLOW` 且 `access_granted=true` 时开放服务。
- 次数/积分必须正式 `consume`。余额足够不是交付凭证；仅在 `SUCCEEDED`、`confirmed=true`、请求号/数量/单位一致时确认核销。
- 操作编号必须在写请求前持久化。`UNKNOWN`、超时、进程重启后查询原 `consumption`，或用同编号和原参数恢复 `consume`；不换号再扣。已确认扣减但交付失败时仅恢复交付。
- 同库交付与唯一回执同事务提交；外部 AI/队列服务用唯一 outbox/任务号，不在数据库事务中等待外部服务。

选择性阅读 [集成参考](references/integration.md)：含 SDK 对应方法、恢复语义和验证清单。在线完整字段以 [官方接入文档](https://ai6666.com/opcpay/docs/) 和 [OpenAPI](https://ai6666.com/opcpay/api/v1/pay/developer/openapi.json) 为准。

用模拟接口验证新增代码：参数与身份伪造、重复点击、扣减成功后丢响应、重启恢复、交付失败，以及无额度。真实付费或核销会消耗用户资金/额度，仅在用户明确授权对应操作后执行，不能为了验证代码自动付款或创建新核销号。最终说明如何配置、如何运行、实际验证结果和未验证项。
